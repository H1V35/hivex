# Compi ingestion-plan baseline before source curation

Both the runner and source snapshot were commit
[`fc59bf3882dadfb3b9487d138fa344586a9a6ddd`](https://github.com/H1V35/compi/commit/fc59bf3882dadfb3b9487d138fa344586a9a6ddd).
Each declared collection was planned separately with `--limit 20 --max-bytes 65536`.
Every continuation was consumed, checking a stable plan hash, contiguous page ranges,
unique source IDs and the complete summary count. No model was invoked.

The three default collections contain 140 selected sources and 1,271,324 source bytes.
Seven inputs exceed the current 32,768-byte extraction limit: Compi ADRs 0042, 0046,
0060 and 0061; the ADR index README; weekly maintenance; and private-memory disposition.
These require source curation or complete declared sections before extraction. This is
an input-size finding, not evidence of semantic completeness or a model context limit.

The `graph` collection here is the authored ADR 0099. The accepted Opus graph and its
cache were neither read directly nor changed. Legacy and dated evidence remain opt-in.
The byte totals exclude native harness instructions, model output and correction attempts;
they must not be presented as tokens, billing or demonstrated savings.
